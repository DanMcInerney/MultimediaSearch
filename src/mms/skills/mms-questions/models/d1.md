# d1-Omni-2B and d1-2B

Notes for the mms-questions skill, for the two d1 models. The `ask` description names which one is configured. Both
answer all eight types (noul, choice, score, text, number, date, box, boxes) and take every question key (`criteria`,
`multiple`, `range`, `step`, `unit`). Both read pictures and video frames, and no model here understands speech. The cards
give an example of each type and no wording rules, so the advice below comes from those examples, the cards' code and probes
of d1-Omni-2B on the developer's laptop (marked "probe", on plain synthetic scenes; d1-2B was not probed).

| | d1-Omni-2B | d1-2B |
| --- | --- | --- |
| Sound | hears it, at 16 kHz | none: a sound is not read |
| Text and single boxes | good | stronger; reports a missing value more often |

## Writing each type

The model reads your `instructions`, then a fixed line for the type (the cards' prompt code). An option's key is never
read, except in a `multiple` choice.

- **noul.** One plain question about one large thing, as the card writes it ("Is the customer asking for a refund?").
  Presence scores among the card's highest picture results (POPE: 89.9, d1-2B 88.7). `criteria` adds `Yes: ...` and
  `No: ...` lines (not measured here); give both keys, as `ask` refuses one side.
- **choice.** The model reads the option texts lettered A, B, C, not the keys (a null text shows its key, `_` as a
  space). Describe each in a few words the others do not share, as the card does ("Charges, refunds, invoices"); terse
  and sentence-long texts scored the same (91%, probe). In the `questions` form always add `none`: "none of these"
  (`ask` adds it to `answers`): without it a blue ball was named red or green 96 times in 100, with it `none` 100 in
  100 (probe). For a position, a 3-way choice (left, centre, right) was right 96%, a 5-way choice 54% (probe).
- **multiple choice.** Each option is its own yes/no, so several can be true. The model reads each key with its text
  (`"saw": a hand saw`), so make the key a word that means it. No `none` is needed: `choices` may be empty. `hit` lists
  options and one of them is enough; `said` names the options of `hit` that were found.
- **score.** The model reads `0 empty`, `1 partly full`: 2 to 10 short phrases of what is visible, lowest first. Use it
  for how full or how messy. A 4-level score for distance was exact 34% of the time, within one level 82% (probe).
- **text, number, date.** Ask for a value written in a text or records window, as the card does ("Who issued the
  invoice?", "How much is due?", "By when must it be paid?"). The model points at one span of at most 512 tokens (32
  for a number or date), or at nothing, so a text without the value does not hit (`hit` is `true`). A number is read
  as written, with a currency sign, `%` or scale word, never converted: "1 234,50 EUR" is 1234.5, but "5 km" and
  "23.5 C" give no number, so ask `text` for those. A date such as 03/04/2026 gives none unless the state says its
  order (the card's invoice says "(day/month/year)"); "20 October 2026" is read as it stands.
- **number with a `range`.** A count or an estimate, with a `step` that divides the range, at most 128 values. Whole
  numbers from 0 to 999 are read as numbers, any other grid as coded bins (a 0.1 step gave the lowest value every time,
  probe). `unit` names what is counted or measured ("beeps", "cm"). `hit` is the least value that counts. The d1-2B
  card says estimates are reliable for counts and scores, less for free quantities (a 0-300 cm range was off by
  0.57 m, probe), and counting pictures scores low (CountQA: 45.4, d1-2B 51.4).
- **box, boxes.** One picture a window; over text or sound the window is skipped and counted. Name the thing, with one
  detail if several look alike, as the card does ("Where is the remote control on the left?"). For `boxes` the card
  writes a noun phrase ("Every cat."), and the model adds "Every one of them, 16 at most, in reading order". `said`
  gives the edges, fractions of the picture from its top left (`at top 0.15, left 0.06, bottom 0.24, right 0.27`, or for
  `boxes` `3 found:` and each box's edges, `at least 16 found:` when the count is a floor); `p` says how sure it is, and
  `look` shows the picture to check. It cannot set the card's `max`, so `boxes` reads 16.

## Context

The model reads your `context`, then the window's text if it has any (a text or records window). A picture or a sound
has no other state, and the card's picture and sound examples use none.

- One short sentence on what the source is. Whether it helps a picture or a sound is not measured. A short state
  answered better in a probe: with one number in it 93% were right, with ten 60%.
- Never the answer. A text, number or date question reads its value from the state, so a value in `context` can be
  what it points at (inferred from how the state is read).
- For a date, the order if the text does not give it: "Dates are written day/month/year."

## The default hit

A yes/no question asks for `hit` left out or `true` to count at the model's default, 0.8. Only for d1-Omni-2B was
0.8 measured; d1-2B's is assumed.

- **d1-Omni-2B's probabilities are compressed** (temperature 3.38). On real frames a pallet that was there scored
  0.37-0.51, a look-alike 0.57-0.64.
- **On real sound, 0.8 passes far more clips than events.** In MultiMediaSearchBench (6 November 2026), over 6,123
  FSD50K clips, asks for coughing gave 121-164 sightings across one agent's asks for 5 coughs (a toilet flushing: 346
  for 14); the coughs found ranked 1st, 9th and 96th of 121 by `p`. Over sound, use `best_first: true` with a `limit` you can
  check. Agents cannot hear `look`'s WAV: check it with your own tools (a spectrogram), or call the sighting unchecked.
- **d1-2B's 0.8 is assumed.** Its calibration temperature is 1.34 against d1-Omni-2B's 3.38, so its 0.8 is not the
  same cut, and which way it differs is not measured. `look` at its first sightings and `candidates` before changing
  `hit`.

## What they see and hear

- A picture is cut to `max_px` (230,400 by default, 640x360), never above the model's cap of 1,638,400 pixels (1080p is cut
  to it). Small text is lost at the default. Raise `max_px` to 921,600 (1280x720, 3-4 times the cost) or 1,638,400 (the cap,
  which `0` gives too; about 8 times the cost) on a narrow range, after a default-size ask has found the moment.
- **d1-Omni-2B hears sound events.** The card scores sound events at 84.5, but short states read aloud at 22.8 (written
  42.0) and long passages at 41.8 (written 83.6), most of all outside Latin script. Ask about a kind of sound (a beep, a
  doorbell, a dog), never about what was said; for that, use `find` on a transcript label if one exists, and otherwise
  say so to the owner. Whether a voice is present is a sound question (the card asks "Does someone speak in the
  recording?"; not measured here), though `ask` warns on speech words. A camera with sound gives sound windows and
  frame windows, and a sound question is put to both: name a mic source when there is one.
- **d1-2B hears nothing.** A mic segment is named in the not-read warning, and a camera's soundtrack in the not-heard
  one. Do not ask it about sound.
- **Weak spots,** so check these with `look`: how far, how fast, which way something moves (d1-Omni-2B recognised
  "away" only 8-16% of the time), counting more than a few things, a small object, what a long spoken passage said, and
  facts that need knowledge (the d1-2B card: those favour larger models).

## Questions in one pass

The model reads 16 questions in one pass. Many questions in one ask cost almost nothing extra (8 took 103 ms
together and 451 ms one by one), but at the seventeenth it reads the window again, so 17 to 32 questions cost twice,
and `ask` warns. Every question with a `hit` must hit in the same window, so one ask holds conditions that go
together; for any of several things use one choice (`answers`, or `multiple`) with `hit` listing them. Another
question beside one, or another order, can move its answer a little (inferred from how the pass packs questions).

## Cost

Measured on the developer's machine with one yes/no question (d1-2B's pictures and text cost what d1-Omni-2B's do): a
640x360 picture 0.053 s plus decoding, 1280x720 about 0.29 s (with 4 questions, where 640x360 took 0.095 s), 1080p cut to
1.6 million pixels 0.48 s, 5 s of sound 0.05 s, 2,000 characters of text 0.044 s. Records and text windows are assumed
linear in characters: about 0.07 s (records) to 0.13 s (text) a window. The default `max_s` of 600 s, counted from the first
answer (loading takes up to a minute first), covers at most about 9,500 windows at the default size, 2,200 at 1280x720.

## Examples

**A sound event** (d1-Omni-2B only; d1-2B finds nothing in sound):

```json
{"question": "Is a doorbell ringing?", "sources": ["mic"], "since": "2h", "limit": 3}
```

**Values read from text** (notes, logs, records and text versions only), all three from one window; `said` holds them:

```json
{"questions": {"payee": {"type": "text", "instructions": "Who issued the invoice?", "hit": true},
               "total": {"type": "number", "instructions": "How much is due?", "unit": "EUR", "hit": true},
               "due": {"type": "date", "instructions": "By when must it be paid?", "hit": true}},
 "context": "An invoice. Dates are written day/month/year.", "sources": ["docs"], "since": "30d"}
```

**A count of sounds, estimated** (d1-Omni-2B only; `said` holds the number and its interval, `3 (2 to 4) beeps`).
Verify with `look`:

```json
{"questions": {"beeps": {"type": "number", "instructions": "How many beeps are there?", "range": [0, 10],
                         "step": 1, "unit": "beeps", "hit": 3}},
 "sources": ["mic"], "since": "2h"}
```

**Where a thing is** (`said` gives the box's edges, and `hit: true` counts a box found):

```json
{"questions": {"mug": {"type": "box", "instructions": "Where is the red mug?", "hit": true}},
 "sources": ["kitchen"], "since": "1h", "limit": 1}
```

**Any of several things, each its own yes/no** (`multiple`; one option in `hit` is enough, no `none` needed):

```json
{"questions": {"kit": {"type": "choice", "instructions": "Which tools are on the bench?",
                       "criteria": {"saw": "a hand saw", "drill": "a power drill"}, "multiple": true,
                       "hit": ["saw", "drill"]}},
 "sources": ["garage"], "since": "1d"}
```
