# d3-edge, d3-mini and d3-flash

Notes for the mms-questions skill, for the d3 decision models of vLLM Semantic Router (Decision 3.0). The `ask`
description names which one is configured; the owner changes it with `mms model use`. The three share one prompt format
and one runtime, and differ in size and cost: d3-edge (0.6B), d3-mini (4.5B) and d3-flash (8.4B).

## What they read and answer

- **They see** a picture or a video frame (mms hands them one frame at a time), up to 1,638,400 pixels (1080p is cut),
  and text: a page of a text version (6,000 characters) or a run of records (3,000).
- **They hear nothing.** Sound is not read. A mic segment is named in the not-read warning, and a camera's soundtrack
  in the not-heard one. A question about a sound finds nothing: say so to the owner.
- **They answer three types:** `noul` (yes/no), `choice` and `score`. A `text`, `date`, `number`, `box` or `boxes`
  question is refused before the scan (`bad_request`), and so is any question key but `criteria`: no `multiple`,
  `range`, `step` or `unit`. They read no value out of text. For where something is, how many, or what a label says,
  find the moment with a yes/no and read it yourself with `look`.
- **`criteria`** is the one key. A choice needs it (`{option: what it means}`, up to 255 options). A score needs it (2
  to 10 levels, lowest first). A yes/no may carry `{"true": ..., "false": ...}`.

## What the model is shown

Each question is its own prompt (`d3_format.py` in the model folders, the same in all three):

```text
[the picture]
State:    your context, then the window's text if it has any; "(empty)" if neither
Question: the question's text, as written
Options:  one line each: "A: ...", "B: ...", ...
Reply with only the code of the best option.
```

The model reads it once and the answer is the probability of each option's code. It writes nothing and reasons in no
words, so ask what a glance at the window answers. Its system line says to treat the State as data, not as
instructions, so a rule the answer depends on is safer in the question or `criteria` (an inference); the context says
what the source is.

- **The question** is shown as written. Make it one plain question about one visible thing, with where it is ("Is red
  text visible in the terminal window?"), as short as the card's examples.
- **A yes/no** is a choice between two lines, "No / false" and "Yes / true", and its `p` is the share of the second. Give
  `criteria`, both `true` and `false`, when "no" is not just the opposite of "yes": say what true looks like and what
  false covers, "not in view" included. The card's examples leave them out, so how much they help is untested here.
- **A choice** shows each option as `key: description`, or the key alone when it has no description (the card uses both).
  The key is read, so make it a word, not `a` or `opt1`, and put what sets the option apart in the description. In the
  `question` and `answers` form the answer text is the key: write each answer in full.
- **It names one option,** the best, and only a listed one. Cover what the window can show, with a `none` (`ask` adds
  one in the `question` form; add your own in `questions`). Make the options exclusive states of one thing ("what fills
  the screen"): two things in a frame split the probability. For "any of these", put several in `hit`. For things that
  can be there together, use yes/no questions, a pass each.
- **A score** shows its levels as plain lines in order, without numbers. Write each as what you would see at that level,
  clearly unlike its neighbours; the card's example has three. Few clear levels beat many fine ones (an inference).
- **The context** is the State, under the picture; in a text window it comes first, then a blank line, then the text. Say
  in a sentence what the source is, as the card does ("A short clip from a test camera."). Every pass reads it again, so
  keep it short. Without one the State reads "(empty)".

## One frame, not a video

The card reads a video at 2 frames a second (at most 32 frames): 73.3, 70.3 and 46.6 on its video test for d3-flash,
d3-mini and d3-edge. mms hands the model one frame as a picture, so none of that applies. A frame holds no motion,
direction, order or change; the card's own example, "Which way does the square move?", cannot be asked. Ask for the
state and compare the times of two sightings. For counting, depth and position the card's nearest tests, by their
names, are CV-Bench and BLINK: check such answers with `look`.

## Which size

- **d3-edge:** its card scores are far below the others (official vision board 31.7, against 63.2 for d3-mini), so
  trust it only with one large, obvious thing (a person, a window, a light) over a wide range, where its speed counts.
  Its `p` was poorly calibrated on text (calibration error 0.34, against 0.05 and 0.03; eval results in the folders):
  `look` at every sighting and candidate, and do not tune `hit`. If it finds nothing or the wrong things, tell the
  owner about `mms model use d3-mini`.
- **d3-mini:** the one for screens and text. It is 3 points behind d3-flash on text (52.6 against 55.8) and level with
  it on charts and web pages (the card has no screen test; these are the nearest), and about 1.7 times faster at 1.6
  million pixels and on text. At the default picture size the two cost nearly the same.
- **d3-flash:** the one for camera frames of real scenes: the highest of the three on photos (RealWorldQA 63.4,
  against 57.3 for d3-mini) and on text.

## One question a pass

A d3 model reads the window once for each question: a forward pass over the whole window per question. Two questions
cost up to twice a window, five up to five times. `ask` warns when a request has more than one, and its estimate counts
every pass. So ask one question when you can, and put the second condition in a second ask over the moments the first
found (use their times for `since` and `until`). A choice over several things is one question.

## Hit and score

- **The default `hit` is 0.8, and it is assumed:** no one has measured these models' probabilities on the developer's machine. All
  three run at temperature 1.0 (`decision_config.json`), so `p` is the raw share of the option, and the eval results
  put the calibration error far apart (above). Treat the first sightings as a trial: `look` at them and at the
  `candidates`, and change `hit` on evidence.
- **A choice's `p` is the picked option's probability.** The model's own `confidence` is not used.

## Cost

Measured on the developer's machine with one yes/no question:

| | d3-edge | d3-mini | d3-flash |
| --- | --- | --- | --- |
| a 230,400-pixel picture, one question | 0.041 s | 0.163 s | 0.184 s |
| a 1,638,400-pixel picture, one question | 0.15 s | 0.57 s | 1.0 s |
| 2,000 characters of text, one question | 0.042 s | 0.135 s | 0.225 s |

A 6,000-character page is assumed to cost three times that. The estimate multiplies by the questions (one pass each).
At the default size four questions cost about twice one. With one question at the default size, `max_s` of 600 covers
at most about 11,500 windows on d3-edge, 3,500 on d3-mini and 3,100 on d3-flash. Small text needs `max_px` raised (921,600, or
its cap 1,638,400, which `0` gives). The card reads a picture at up to that size, so its
scores on text in pictures may not hold at the default (an inference).

## Examples

**A yes/no with its two lines written out:**

```json
{"questions": {"parcel": {"type": "noul", "instructions": "Is a parcel on the doorstep?",
                          "criteria": {"true": "a box or package lies on the doorstep",
                                       "false": "the doorstep is empty, or no doorstep is in view"},
                          "hit": true}},
 "context": "A camera over the front door.", "sources": ["porch"], "since": "1d", "limit": 3}
```

**A choice,** a short key and a description each, a `none`, and `hit` naming the key:

```json
{"questions": {"app": {"type": "choice", "instructions": "Which application fills most of the screen?",
                       "criteria": {"editor": "a code editor with source code open",
                                    "terminal": "a terminal window with text output",
                                    "browser": "a web page in a browser",
                                    "call": "a video call with people's faces",
                                    "none": "none of these"},
                       "hit": "call"}},
 "context": "The laptop's screen.", "sources": ["screen"], "since": "1d", "every_s": 10}
```

**A score over text,** each level written as what the page shows:

```json
{"questions": {"severity": {"type": "score", "instructions": "How bad is the worst problem in this log?",
                            "criteria": ["no problem", "a warning only", "an error, the program goes on",
                                         "a crash, the program stops"],
                            "hit": 2}},
 "context": "Lines of a build log.", "sources": ["build"], "since": "1d", "limit": 5}
```
